# PR-031.3 — The gold swap sent Glue a field Glue does not accept

**Unplanned fix, not a roadmap item.** Found on 2026-09-24 while recovering the sorteo that
PR-031.2's scraper outage had stranded: the recovery run got all the way to the last state
and failed there.

```
ParamValidationError: Unknown parameter in TableInput: "IsMaterializedView", must be one of:
Name, Description, Owner, LastAccessTime, LastAnalyzedTime, Retention, StorageDescriptor,
PartitionKeys, ViewOriginalText, ViewExpandedText, TableType, Parameters, TargetTable,
ViewDefinition
  File "/var/task/purge_and_load.py", line 400, in promote
    glue.update_table(DatabaseName=database, TableInput=_table_input(staged, table))
```

Nothing about this is scraper-related. It would have failed the same way on the next
scheduled Thursday run, and on every one after it.

---

## 1. A denylist where an allowlist belonged

`_table_input` took the whole GetTable response and subtracted the keys known to be
read-only. Its own comment argued for the design:

> a field added to a future Glue API version keeps flowing through instead of being dropped

That sentence describes the bug as if it were the feature. Sometime between 2026-09-17 (the
last successful run) and 2026-09-24, Glue's GetTable response began carrying
**`IsMaterializedView`**. It was on no denylist, so it flowed through into `update_table`,
which rejects it. With subtraction, **every field AWS adds is a scheduled outage** — the
failure arrives on AWS's release calendar, not on a deploy of ours.

`_partition_input` had the same shape and the same latent bug on the path that runs
immediately after.

## 2. What changed

Both are allowlists now.

| | Fields sent |
|---|---|
| `_TABLE_INPUT_FIELDS` | the full `TableInput` shape (14) — identical behaviour to the denylist, minus the unknown fields |
| `_PARTITION_INPUT_FIELDS` | `Values`, `StorageDescriptor`, `Parameters` — exactly what the old subtraction left behind |

The partition allowlist is deliberately narrower than what Glue accepts:
`LastAccessTime` and `LastAnalyzedTime` are valid but were dropped before, and an outage fix
is the wrong place to start publishing timestamps nothing has ever read.

`test_every_field_we_send_is_one_glue_accepts` asserts both stay **subsets** of botocore's
own shapes — the same model that produced the error above, read from the bundled JSON with
no credentials and no network. A subset rather than an equality on purpose: a field AWS adds
that we never send cannot break anything, and should not turn CI red.

## 3. What the failure left behind

Nothing corrupt, and this is by design: `promote` is the last state, and it failed on its
first call, *before* `_move_partitions`.

| | State after the failure |
|---|---|
| raw / silver | current, including the sorteo the run ingested |
| Published `gold_*` tables | all 7 still pointing at the 2026-09-17 generation — consistent, one generation stale |
| Staging tables | 3 × `gold_*__stg_<run>` left in the catalog, data under `gold/<table>/run=<run>/` |

The staging tables are disposable — the swap deletes the catalog entry last precisely so a
failure leaves them available to inspect. They are cleaned by the next successful run's
`prepare`, which empties its own staging prefix.

## 4. Apply

The gold Lambda ships in the Terraform-managed package, so this needs a build and an apply,
not an environment change:

```bash
make build
terraform -chdir=terraform plan     # expect this change plus the usual artifact churn
terraform -chdir=terraform apply
```

Then re-run the pipeline. The run re-extracts before it reaches gold, so it costs the usual
20 credits on the PR-031.2 proxy profile.

## 5. Verify

```bash
# 1. The published tables should move to the new generation and the staging entries go away.
aws glue get-tables --database-name lottery_santalucia_db \
  --query 'TableList[?starts_with(Name, `gold_`)].{Name:Name,Updated:UpdateTime}' --output table

# 2. No __stg_ entries should survive a successful run.
aws glue get-tables --database-name lottery_santalucia_db \
  --query 'TableList[?contains(Name, `__stg_`)].Name' --output text   # expect: empty
```

## 6. The wider point

This is the second time in one evening that a **response** from someone else's system grew a
field or a behaviour our code took as fixed — Cloudflare's tolerance for headless rendering
in PR-031.2, Glue's table schema here. Both were written as "tested, therefore settled".
Where this repo reads someone else's payload, prefer naming what it wants over subtracting
what it knows about today.
